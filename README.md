# fundtrail

**Status: early prototype (v0.1.0).** Interfaces and output formats will change.
It has not been audited and has been used on one real incident so far, partly by hand.

fundtrail is a small, read-only on-chain security monitor written in Python. It talks to
ordinary public JSON-RPC endpoints and needs no API keys. It never signs or sends transactions.

| Command | What it does | Status |
|---|---|---|
| `tips` | Block-tip health check for Ethereum, Arbitrum, Optimism and Base (BNB Chain and Polygon optional) with fallback endpoints. JSON output. | Working |
| `bounties` | Diffs the Immunefi public program listing against a saved snapshot: new, removed and changed programs. | Working |
| `trace` | Follow-the-funds tracer: native transfers and ERC-20 `Transfer` logs, N hops, labels known mixers and bridges. Graph JSON plus markdown. | Working, limited (see below) |
| `alerts` | Pluggable alert sources; ships an RSS/Atom feed source with keyword filters. | Basic |
| `report` | Renders a markdown incident report from a trace graph. | Basic |

## Quickstart

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -e ".[dev]"
pytest -q

fundtrail tips                      # main chains
fundtrail tips --all                # plus BNB Chain and Polygon
fundtrail bounties                  # first run saves a baseline snapshot
fundtrail trace 0xADDRESS --chain ethereum --from-block latest-50 --hops 2 \
    -o graph.json --report report.md
fundtrail report graph.json -o report.md
fundtrail -c config.example.yaml alerts
```

Configuration is YAML; see `config.example.yaml`. Anything you leave out falls back to defaults
(publicnode endpoints first, then a second public endpoint per chain).

## How tracing works

- **Tokens:** `eth_getLogs` for `Transfer` events where the address is the sender. The block
  range is chunked, and the chunk is halved when a node rejects it.
- **Native coin:** plain JSON-RPC has no per-address transaction index, so fundtrail scans full
  blocks in a bounded window (`max_blocks`, default 500) and indexes value-bearing transactions
  by sender. This is slow on public RPCs; keep windows small.
- **Graph walk:** breadth-first, up to `--hops`. Only transfers at or after the block where an
  address first received funds are followed. Expansion stops at labelled mixers and bridges and
  at contracts. EIP-7702 delegated accounts (code starting `0xef0100`) count as accounts, not contracts.
  Very busy addresses are cut to the `max_fanout` largest transfers, and a note is added.
- **Rate limits:** a minimum interval between calls, backoff on HTTP 429, and fallback to the
  next endpoint on connection errors.
- **Labels:** `fundtrail/data/labels.yaml` lists Tornado Cash on Ethereum and BSC, and the main
  canonical bridges, each with a source URL. Every entry was checked on-chain (`eth_getCode` on the listed
  chain) and against official docs or explorer name tags on 11 Oct 2026. Add your own with `--labels my.yaml`.

## Worked example: 79thVault (BNB Chain, October 2026)

`examples/79thvault/report.md` is the report from a manual investigation of the 79thVault
exploit on BNB Chain. That investigation was done with one-off scripts against an archive RPC
**before this tool existed**. Its public on-chain flows are kept in `tests/fixtures/79thvault_flows.json`;
`fundtrail report --evidence` converts that into the fundtrail graph
format, and the tracer tests replay a subset of its flows from fixtures. So this example shows the
output format. It is not proof that `fundtrail trace` alone would have found these flows.

```bash
fundtrail report tests/fixtures/79thvault_flows.json --evidence \
    --graph-out graph.json -o report.md
```

## Limitations

- Native transfers made inside contracts (internal transactions) are not seen. That needs
  `debug_traceTransaction` or `trace_*`, which most public RPCs do not offer.
- The native-transfer scan is a full block scan. It does not work for ranges of thousands of
  blocks on free endpoints. Token tracing covers longer ranges much better.
- There is no swap or bridge decoding. Value through a DEX or a bridge ends the trail at that contract.
- The label set is small and incomplete. An unlabelled address could still be an exchange or a service.
- Amounts are raw token units divided by `decimals()`. There is no USD pricing.
- `bounties` depends on Immunefi's public JSON listing staying in its current shape.
- `alerts` only polls feeds and removes duplicates. There is no scheduling or notification delivery yet.
- So far it has been tested on fixtures and a few small live runs. It has not been checked
  against published post-mortems.

## Roadmap

These follow the milestones in the project's grant proposal (Ethereum and L2 focus):

1. **Open-source tracer for Ethereum and L2s.** A tagged MIT release, run by an independent
   reviewer on at least 3 past Ethereum or L2 exploits, that matches each post-mortem's attacker
   addresses and mixer or bridge deposits. Planned work: trace-API support for internal
   transfers, more labels, and replay tests built from those exploits. *Not met yet.*
2. **Live incident reports.** At least 6 public reports on Ethereum or L2 exploits over $100,000,
   each within 24 hours of the first public alert, plus a public latency log (median of at most
   30 minutes from first alert to first packet). Needs `alerts`, then `trace`, then `report` to
   run as a pipeline. *Not started.*
3. **Responders using packets.** Outside organisations (for example SEAL 911, exchange security
   teams, or protocols) confirm that they used a report in a live incident. *Not started.*
